# ADR-0011 本文量は「表示行」モデルで推定し、フォントサイズはスライド単位で変えられる

## 状況
行数だけの判定はフォントサイズと折り返しを無視し、実際の溢れと合わない。DOM 実測はプレビューのフォントが PowerPoint と違い、Python 側で再現できない。

## 決定
- 容量 = 本文枠高さ ÷（フォント pt × 1.2）、使用量 = 各行の折り返し後の行数（全角 1em・半角 0.55em・字下げ 1.5em/階層）。`src/model/fit.ts` と `tools/export_pptx.py` に同じ計算を置く。
- フォントサイズは `{size=N}` > frontmatter `fontSize` > マスター bodyStyle lvl1 > 18pt。マスター取り込み時に bodyStyle と normAutofit を解析する。
- 本文枠はレイアウトと画像の縦横比から `src/model/boxes.ts` で求め、プレビュー・分割判定・出力で共通。
- エディタにゲージ行と分割マーカー、スライド区切りの点線を装飾として描く。データはストアから流し、エディタは描くだけ。

## 結果
- 目安の精度は「1 行程度のずれ」。厳密さより一貫性（ゲージ・プレビュー・pptx 警告が一致）を優先。
- 自動分割でスライド id が変わるため、選択維持を `reselect` で行う（E2E で発見した不具合）。
