# ADR-0032 見本マスターを発表用と報告用の 2 種類にする

## 状況
- 見本マスター（ADR-0031）は本文 18pt の 1 種類だけだった。18pt は離れて読むスライド向けの大きさで、手元で読む報告資料には大きすぎる。
- 報告資料は読まれ方が違う。会議で映して読み上げるのではなく、机の上でじっくり読まれ、あとから「3 ページ右下の図」と参照される。求められる版面も違う。
  - タイトルは名詞（「〇〇の件について」）ではなく結論の 1 文になる。20pt 前後で 2 行入る帯が要る。
  - 本文は 11pt 前後で、箇条書きを階層化して構造で見せる。1 ページに入る行数が多い。
  - 図と解説、見出しと本文は近づけてまとまりを作る（近接）。タイトルと本文の間隔も詰める。
  - 色はベース・メイン・アクセントの 3 色以内。装飾・枠線・影は足さず、余白と文字の大小だけで階層を作る。
  - ページ番号は必須。
- 一方で発表用の見本を報告用に置き換えると、離れて読む用途が無くなる。両方必要。

## 決定
1. 見本を 2 つにする。`examples/sample-master.pptx`（発表用・本文 18pt）はそのまま、`examples/report-master.pptx`（報告用・本文 11pt）を足す。レイアウト名・役割・枠の選び方は同じで、違うのは密度と文字の大きさだけ。
2. 1 つのスクリプト（`scripts/make_sample_master.py`）が両方を作る。グリッドの作り方は ADR-0031 のまま共有し、プロファイル（余白・間隔・溝・帯の高さ・文字の段）だけを変える。
   - 発表用: 余白 6%、タイトルと本文の間隔 2%、溝 4%、表紙 40 / 章 36 / タイトル 32 / 本文 18pt。
   - 報告用: 余白 5%、間隔 1.2%、溝 3%、表紙 28 / 章 20 / タイトル 20 / 本文 11pt（第 2 階層 10、第 3 階層 9）。
   - 箇条書きのぶら下げ幅も文字サイズに比例させる（1.6em）。Office 既定の 0.375 インチは 32pt の本文に合わせた値で、11pt では中黒と文章が離れて 1 行に見えない。
3. 報告用はテーマ色をベース（白・淡灰）・メイン（墨）・アクセント 1 色（紺）に絞り、残りのアクセント枠は同系の灰で埋める。この配色は `theme.json` を通って図生成ツールにも渡るので、生成した図も 3 色に収まる。発表用は Office の配色のまま（`tests/unit/theme.test.ts` が固定している）。
4. 図は専用レイアウトを作らない（ADR-0006 のまま）。本文枠をフッタの手前まで広く取り、ツールが Body-Text の上に図と本文を配置する。
5. アプリは両方を同梱し、設定のマスターに「見本（発表用）を取り込む」「見本（報告用）を取り込む」を並べる。どちらも同名ファイルがあるときは上書きしない。
6. 紹介ページのツアー画像と README のデモ GIF は報告用マスターで撮る。密度の高い実務の資料に近く、ツールの用途（報告用スライド）を正しく見せられる。

## 結果
- 「タイトル＝結論」で書くと 20pt の帯に 2 行で収まり、1 ページに 25 行前後の本文が入る。
- 報告用で書いた資料を発表用マスターに切り替えると、本文が 18pt になり自動分割が増える。frontmatter の `master:` を変えるだけで切り替わるので、同じ Markdown から両方を出せる。
- ツアー画像は装飾入りの見本ではなく報告用で撮るため、マスターの装飾（ロゴ・帯）を見せる画は無くなる。装飾の確認は `examples/decorated-master.pptx` を取り込んで行う。
- deck.json の契約は変えない（version 2 のまま）。
