# ADR-0029 起動画面は「作る」と「開く」の 2 つにし、資料の無いフォルダは空の枠で始める

## 状況
- 起動画面は「Markdown を開く」（青い主ボタン）「新しく作る」「フォルダを開く」「サンプルを見る」を横に並べていた（ADR-0013）。ADR-0015 で新規作成が「フォルダを選んで `deck.md` を作る」になり、資料の単位はフォルダだと明確になったが、主ボタンは任意の Markdown ファイルを開く操作のままだった。
- 「Markdown を開く」と「フォルダを開く」はどちらも既存の資料を開く操作で、違いが画面から分からず、ボタンの下に長い注記を置いて説明していた。
- 資料のファイルが無いフォルダを開くと、そのとき画面にある文書（起動直後は組み込みサンプル、別の資料を開いていればその中身）が書き込まれた。「新しく作る」は空の枠なので、作る経路が 2 つあって結果が違い、サンプルを黙って出さない方針（ADR-0013）にも反していた。
- 最近開いたものはファイル名を見出しにしていたため、ほとんどが `deck.md` になって見分けられなかった。パスは `direction: rtl` の副作用で、先頭の `/` や `~/` が末尾に回って表示されていた。

## 決定
1. 起動画面の操作は「新しい資料を作る」（主ボタン）と「資料を開く」の 2 つにし、それぞれ何が起きるかを 1 行で添える。注記は無くし、「サンプルを見る」は区切り線の下に控えめに置く。ブラウザ版は作る経路が無いので「フォルダを開く」を主ボタンにする。
2. 「資料を開く」は 1 つのダイアログで、資料のフォルダかその中の Markdown ファイルを選ぶ（`dialog:openDeck`。macOS は `openFile` と `openDirectory` を併用し、他の OS はファイルだけ）。フォルダなら `deck.md`、ファイルならその名前で開く。戻り値はコマンドライン引数と同じ `{ root, deckFile }` で、main の同じ判定（`deckEntry`）を通す。`dialog:openMarkdown` は削除し、ツールバーの開くボタンも同じ操作にする。
3. 資料に入るとき（開く・作る・コマンドライン引数）に資料のファイルが無ければ、「新しい資料を作る」と同じ空の枠（`newDeckTemplate`。題はファイル名かフォルダ名）で作る。開いている資料のファイルが外で消えた後の再読み込みは、従来どおり画面の文書を書き戻す（作業中の内容を空の枠で置き換えない）。
4. 最近開いたものはツールバーと同じ `フォルダ名/ファイル名` を見出しにし、フォルダの場所を添える。パスは `<bdi>` で囲み、表示の向きが崩れないようにする。

## 結果
- 主ボタンが「資料 = フォルダ」の前提と一致し、選択肢が 3 つから 2 つに減った。任意の名前の Markdown を開く経路（ADR-0015 決定 4）は「資料を開く」の中に残る。
- 組み込みサンプルが資料フォルダに書き込まれることは無くなった。サンプルは「サンプルを見る」で見るだけになる。E2E はサンプルの章・スライド名を前提にしているため、テスト側でサンプルの `deck.md` をフォルダに置いてから開く。
- ADR-0013 決定 1 の起動画面の項目と、決定 2 の「フォルダを開いたときの雛形は組み込みサンプル」をこの ADR が置き換える。ADR-0015 決定 4 の「Markdown を開く」は「資料を開く」に含まれる。
