# ADR-0030 手持ちのテンプレートからのマスター変換は、元ファイルを土台にする専用スクリプトで行う

## 状況
- `docs/master-guide.md` の「AI に頼む（プロンプト）」は、変換のやり方を毎回 AI に書き下ろさせていた。スライドの削除（`_sldIdLst` から外して `drop_rel`）とレイアウトの複製は XML 操作が要る、とだけ書いてあった。
- 実環境で試したところ、二つの壊れ方が出た。
  1. 生成されたスクリプトが XML の名前空間を取り違え、期待どおりのファイルにならなかった。手で名前空間を書くと、python-pptx では通っても PowerPoint が読めないファイルになる。
  2. 元のテンプレートの本文枠（説明用の狭い枠など）をそのまま引き継いだため、`bodyBoxFor`（`src/model/boxes.ts`）が見積もる行数が 1 行になり、自動分割が 1 行ごとにページを切った。
- どちらも「元ファイルを AI がその場の判断で書き換える」ことが原因で、プロンプトの文面を直しても再発しうる。

## 決定
1. 変換は `tools/convert_master.py` が行う。プロンプトはこのスクリプトを実行させるだけにし、使えない環境のための条件（枠の寸法と `qn()` の指定）を添える。
2. 土台は元のファイルにする。パッケージをまたいだコピーをしないので、テーマ・フォント・配色・ロゴ・ヘッダ・フッタは触らずに残る。見本 pptx を骨格にして装飾を移植する方式は採らない（画像パーツと rels のコピーが、今回壊れた領域そのものだから）。
3. スクリプトが変えるのは mdslide が読む所だけにする。
   - 役割の近いレイアウトを名前と枠の構成から選び、`Cover / Agenda / Section / Body-Text / Body-2col` に改名する。足りない役割は本文レイアウトのパーツを複製して作る（rels ごと複製し、マスターの `sldLayoutIdLst` に登録する）。
   - 役割として読まれてしまう名前の残りのレイアウトは `Unused-` を付けて避難させる（先にあるものが使われるため）。
   - 本文の枠は元の大きさを引き継がず、`src/layouts/geometry.ts` と `src/model/boxes.ts` と同じ規則（余白 5%、タイトルとの間隔 2%、ヘッダ・フッタとの間隔 1%、2 段組みの間隔 3%、いずれもスライド幅に対する比）で置き直す。
   - 本文に使わない枠（説明用・小見出し・画像）は外す。日付・フッター・スライド番号は残す。表紙だけは枠を動かさない（意匠が最も強く出る場所のため、サブタイトルが無いときだけ足す）。
   - 通常のスライドはすべて削除する。
4. 幾何の定数と役割名の判定は TypeScript 側と二重に持つ。`reads_as_role` は `roleFromLayoutName`（`src/master/importMaster.ts`）の写しとして保つ。

## 結果
- 変換が決定論的になり、名前空間と本文枠の事故は `tests/python/test_convert_master.py` が固定する。
- 変換後に「本文およそ N 行」が出るので、ヘッダ・フッタの帯が厚すぎるマスターはその場で分かる。
- 元テンプレートの章（Section）に付いていた説明用の枠は落ちる。mdslide が流し込まない枠は、書き出した pptx で空のまま残るため。
- deck.json の契約は変えない（version 2 のまま）。
