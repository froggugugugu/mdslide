# ADR-0033 手持ちのテンプレートの変換を設定シートから実行する

## 状況
- 変換は `tools/convert_master.py`（ADR-0030）が担い、確実に動くようになった。しかし実行手段は端末だけで、配布アプリの利用者には「アプリの中の `Contents/Resources/tools/` を Python で叩く」という案内しか無かった。
- 一方で、アプリはすでに書き出しで Python を起動している（`export:run`）。使う Python は起動時の確認（ADR-0019）で決まっており、同じものをそのまま使える。
- マスターの取り込み（`dialog:importMaster`）は、利用者がパネルで選んだ任意の pptx を保管フォルダへコピーする。選択そのものが同意なので、変換元も同じ扱いにできる。

## 決定
1. 設定（⌘,）のマスターに「テンプレートから変換」を置く。押すとファイルパネルが開き、選んだ pptx を変換して保管フォルダに入れ、一覧を読み直す。既定のマスターがまだ無ければ既定にする。
2. main に `master:convert` を足す。書き出しと同じ Python とスクリプト解決（配布時は `process.resourcesPath/tools`）を使い、`{ name, code, stdout, stderr }` を返す。パネルを閉じたときは null。
3. 変換元は guard の対象にしない（利用者がパネルで選んだファイルだから。`dialog:importMaster` と同じ扱い）。書き込み先の保管フォルダは guard する。
4. 同じ名前のファイルが保管フォルダにあるときは変換しない。手を入れたマスターを黙って失わないため、見本の取り込みと同じ規則にする。
5. 変換は Python を必要とするので、ブラウザ版の `MasterSource` には `convert` を持たせない。UI はその有無でボタンを出し分ける。
6. 端末から実行する道は残す。ガイドには「アプリからの実行」を先に、コマンドを後に書く。
7. あわせて変換側の役割選定を直す（ADR-0030 の細部の改定）。UI から実際のテンプレートを変換して分かった二つの穴を塞ぐ。
   - 画像を主役にしたレイアウト（`pic` の枠を持つ Office の「Picture with Caption」など）は本文系の役割に選ばない。タイトルと本文 1 つを持つため、候補が少ないと目次に選ばれてしまっていた。
   - タイトルが上 1/3 に無いレイアウトは減点し、それでも選ばれたときはタイトルを標準の帯へ移してから本文枠を測る。「Picture with Caption」はタイトルが高さの 70% にあり、その下から本文を取ると 3 行の帯になっていた。

## 結果
- 配布アプリだけで、手持ちのテンプレートをマスターに変換して使い始められる。
- 失敗したときはスクリプトの stderr をそのまま設定シートに出す（Python が無い場合は「書き出し」タブの案内に従う）。
- ファイルパネルは main が開くので、レンダラは任意のパスを扱わない（ADR-0026 の方針は変わらない）。
- deck.json の契約は変えない。
