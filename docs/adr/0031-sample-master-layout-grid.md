# ADR-0031 見本マスターの枠を PowerPoint 既定から一つのグリッドに置き換える

## 状況
- `examples/sample-master.pptx` は python-pptx の既定テンプレート（Office テーマ）の枠を 16:9 に広げただけで、PowerPoint の既定値がそのまま出ていた。見本はアプリが同梱し、「見本を取り込む」で最初のマスターになるので、これが mdslide の第一印象になる。
- 実際の値を測ると、デザインの基本原則（整列・近接・反復・対比）が効いていなかった。
  - 左余白が表紙だけ 12.5%、本文・目次・章は 6.9%。レイアウトごとに縦の基準線が違う。
  - 2 段組みの溝がスライド幅の 1.2%（0.42cm）しかなく、外余白より狭い。2 列が 1 つの塊に見える。
  - タイトル枠の高さが本文で 19.3%、章で 41.6% と過大で、行数によって文字の位置が上下に動く。
  - 本文の既定が 32pt。mdslide が既定で仮定する 18pt と食い違い、行数の見積もりも書き出しの文字も過大になる。
  - テーマフォントが Calibri。macOS には無いので、実際には別のフォントに置き換わって表示される。

## 決定
1. 枠は一つのグリッドから導く。余白はスライド幅の 6%（左・右・上で同じ光学量）、タイトルと本文の間隔 2%、2 段組みの溝 4%。考え方は `src/layouts/geometry.ts` の `MARGIN` / `TITLE_GAP` と同じで、値を見本用に定める。
2. すべてのレイアウトを同じ左の基準線に載せる（表紙と章も 6%）。反復と整列を装飾ではなく座標で作る。
3. タイトル帯は 2 行ぶん（32pt × 2 行）に固定し、下端そろえ（`anchor="b"`）にする。1 行でも 2 行でもベースラインが動かない。
4. 表紙と章の文字は黄金分割の上側の線（0.382 H）に置く。章は表紙より上（0.30 H）に置き、同じ見た目にならないようにする。幅は本文と同じにし、左そろえを明示する。幅を φ で絞ると日本語のタイトルが語中で折り返し、Office 既定のままだと副題が中央そろえで左の基準線から外れる（どちらも実際に描いて確かめた）。
5. 文字は表紙 40pt / 章 36pt / タイトル 32pt / 本文 18pt と段を作る（Office 既定は章が表紙と同じ 40pt、章の説明文だけ 20pt で、段になっていない）。18pt は mdslide が既定で仮定する大きさで、見積もりと書き出しが一致する。
6. テーマフォントは Helvetica Neue / Hiragino Sans にする。配色は Office 既定のまま（見本の目的は配色見本ではなく、`theme.test.ts` が固定している）。
7. 本文レイアウトの枠はスライドマスター側に置き、レイアウトは位置を持たずに継承する。マスターの作り方として正しく、`importMaster` の継承経路も通る（`tests/unit/importMaster.test.ts` がこの形を読む）。
8. フッタ行（日付・フッター・ページ番号）の y と高さは動かさない。装飾入りの見本と `boxes.test.ts` がこの行を土台にしている。x だけ新しい余白に合わせる。

## 結果
- 本文に入る行数の目安は 14 行から 13 行に減る（枠をフッタから 2% 離したため）。
- 装飾入りの見本 `examples/decorated-master.pptx` は作り直しが必要。あわせて `make_decorated_master.py` の `set_lvl1` が既存の `lvl1pPr` を再利用せず重複させる不具合を直した（見本が `lvl1pPr` を持つようになって表面化した）。
- 手持ちのテンプレートを変換する `tools/convert_master.py`（ADR-0030）は元ファイルの意匠を尊重する立場なので、このグリッドは見本にだけ適用する。変換側の本文枠の規則は変えない。
- README と紹介ページの画像は、必要になった時点で `scripts/make_tour_images.py` / `make_demo_gif.py` で撮り直す。
- deck.json の契約は変えない（version 2 のまま）。
- ADR-0023 の決定 3（見本の枠は PowerPoint の 16:9 の位置に置く）は、この ADR が置き換える。レイアウト名と本文枠の選び方（決定 1・2）はそのまま有効。
